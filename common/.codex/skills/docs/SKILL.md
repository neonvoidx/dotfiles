# Documentation Preferences

## Goal
- Produce docs that are accurate, task-oriented, and easy to maintain.

## Workflow
1. Audience + intent:
- Define who the doc is for and what task it should enable.
2. Structure:
- Lead with prerequisites and quick-start, then details and troubleshooting.
3. Accuracy check:
- Verify commands, paths, and examples against current code or state.
4. Maintainability:
- Keep sections concise and avoid duplicated truth across files.

## Constraints
- Prefer examples that are executable and current.
- Call out version and environment assumptions explicitly.

## Done Criteria
- A user can complete the target task from the doc alone.
- Examples validated.
- Open questions and follow-ups documented.
- New reusable doc lessons captured in memory if discovered.
